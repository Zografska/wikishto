# P0.2 — Contracts: API types and puzzle format
Model: opus (plan mode) · Depends: P0.1 · owner approves before merge

**Goal:** the types every other brief codes against.

**Read:** `docs/SPEC.md` sections "Gameplay rules", "Input and matching", "Backend" (allowed exception), `shared/index.ts`.

**Touch:** `shared/api-types.ts`, `shared/puzzle.ts`, `shared/puzzle-format.md`, `shared/fixtures/puzzle.sample.json`, `shared/index.ts`, `shared/contracts.test.ts`.

**Contract:**
- Endpoints: `GET /puzzle/today`, `GET /puzzle/:date`, `POST /guess`, `POST /solve`, `GET /health`. Typed request + response + error `{error, message?}`.
- Skeleton token: index, type `word|number|punct|latin`, letter count (word/number), `inTitle`, shown text for `punct`/`latin` and the separator inside numbers. No word text, no lemma.
- **Gap to fix:** the spec's `/guess` returns only hit slots, but the client must display the revealed surface form (guess куќа reveals "куќата").
  Hits are `{slot, text}[]`. Near misses are `{slot, sim, kind:'content'|'function'}[]`; the client paints the guess word itself.
- `/guess` status: `accepted|unknown|invalid`. `/solve` returns title, full article text (as tokens) and Wikipedia URL.
- Puzzle blob (KV `puzzle:mk:<date>`), versioned with `v`: tokens (surface, type, lemma, title flag), `lemmaSlots: lemma → slots`,
  `near: guessLemma → [slot, sim×100][]`, URL, article id. P1.3 may change the storage layout; keep `v`.

**Acceptance:**
- `puzzle.sample.json`: a made-up Macedonian sentence of ~20 tokens incl. a number `2,1`, a hyphenated compound (two blocks), a Latin token, 2 title words. Typechecks via `satisfies`.
- `puzzle-format.md` documents every field in 40 lines or fewer with one example.

**Done-check:** `pnpm -C shared typecheck && pnpm -C shared test -- --reporter=dot`

**Out of scope:** implementations.
