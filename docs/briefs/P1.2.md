# P1.2 — Worker CPU benchmark
Model: sonnet · Depends: P1.1

**Goal:** know whether a puzzle blob can be read and used inside the Free plan's 10 ms CPU per request.

**Read:** `shared/puzzle.ts`, `worker/src/index.ts`.

**Touch:** `worker/bench/*`, `worker/package.json` (script `bench`), `pipeline/spike/RESULTS.md` (create with an empty numbers table).

**Contract:**
- Workers timers don't advance during pure CPU work, so in-Worker timing is meaningless. Measure in two ways:
  1. `pnpm -C worker bench <dir>`: a Node script (same V8) that, for each blob, reports median of 20 runs for `JSON.parse` and for one guess lookup (hits + near filter).
  2. A temporary route `/bench/:file` behind an env flag that parses a blob from KV, for the owner to deploy to a preview Worker and read CPU time in the dashboard. Document the steps in RESULTS.md.
- Also time a single D1-style lookup of a form in a 100k-row `vocab.tsv` loaded as a Map, as a baseline.

**Acceptance:** bench prints a table: file, bytes, gzip bytes, parse ms, lookup ms.

**Done-check:** `pnpm -C worker bench ../pipeline/out/spike`

**Out of scope:** real endpoints.
