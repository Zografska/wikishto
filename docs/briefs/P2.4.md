# P2.4 — `schedule` and `upload` commands
Model: sonnet · Depends: P2.3

**Goal:** built puzzles → dated KV keys, safely and repeatably.

**Read:** `shared/puzzle-format.md`, `pipeline/wikishto/cli.py`, `pipeline/wikishto/build.py` (signatures only).

**Touch:** `pipeline/wikishto/{cli,schedule,upload}.py`, `pipeline/tests/test_schedule.py`, `pipeline/tests/test_upload.py`, `pipeline/overrides.example.csv`.

**Contract:**
- Dates are Europe/Skopje calendar dates. Fill N days (default 60) after the last scheduled date in KV, or from tomorrow.
- `overrides.csv` (date, article id) pins first; the rest assigned with a fixed seed from config.
- Never reuse an article: read existing ids from KV key metadata (`wrangler kv key list --prefix puzzle:mk:`); every upload sets metadata `{id}`.
- `upload` writes a bulk JSON and runs `wrangler kv bulk put` (`--preview` for the preview namespace, `--dry-run` prints keys only). Respect 1,000 KV writes a day.
- `upload-vocab --part 1|2` runs `wrangler d1 execute wikishto --remote --file out/vocab.partN.sql`.
- The agent never runs remote commands; tests mock the subprocess.

**Acceptance:** same seed → same schedule; overrides win; existing dates and used ids are skipped; bulk JSON shape and metadata correct; dry run touches nothing.

**Done-check:** `cd pipeline && uv run pytest -q -x tests/test_schedule.py tests/test_upload.py`
